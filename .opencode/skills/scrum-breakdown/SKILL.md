---
name: scrum-breakdown
description: Break down features and plans into sprint-ready tickets with story points (Fibonacci), dependencies, and acceptance criteria. Do NOT use for technical planning or coding.
compatibility: opencode
---

## When to Use
- After planning skill produces an implementation plan
- Feature needs splitting into tasks
- Sprint planning or backlog refinement
- Story point estimation

## Capacity Reference
- Core team: ~20 SP / sprint
- Angular (2 devs): ~30 SP / sprint
- React Native (1 dev): ~15 SP / sprint

## Rules
- Max 8 story points per ticket
- Each ticket completable by one developer
- Testing ticket for every feature ticket
- `[SECURITY]` prefix for sensitive tickets
- Clear acceptance criteria and definition of done
